# MonitorEO en Python, QGIS, R y modelos de lenguaje

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23814894.svg)](https://doi.org/10.5281/zenodo.23814894)

<p align="center"><img src="src/monitoreo/logos/monitoreo_obsnev.png" alt="Observatorio de Cambio Global de Sierra Nevada, Universidad de Granada, Ministerio de Ciencia, Innovación y Universidades, Cofinanciado por la Unión Europea, Agencia Estatal de Investigación y Junta de Andalucía" width="850"></p>

MonitorEO-OBSNEV is an open monitoring tool of Essential Biodiversity Variables based on satellite sensors and models generated by the University of Granada. It enables citizens, managers, and scientists to create maps and graphs of key ecosystem metrics to support decision-making.

MonitorEO-OBSNEV es una herramienta abierta de monitorización de Variables Esenciales de la Biodiversidad basada en sensores satelitales y modelos generados por la Universidad de Granada. Permite a la ciudadanía, gestores y científicos crear mapas y gráficos de métricas clave de los ecosistemas para apoyar la toma de decisiones.

[Manual con ejemplos (wiki)](https://github.com/monitoreo-obsnev/monitoreo/wiki) · [Cómo citar](#cómo-citar--how-to-cite) · [Agradecimientos](#agradecimientos--acknowledgements)

Las variables de satélite de MonitorEO
(OBSNEV, Universidad de Granada), calculadas con Google Earth Engine desde cuatro herramientas que usan **las mismas
funciones** (`monitoreo.services`). El manual de cada una, con tutoriales y ejemplos, está en la
[wiki](https://github.com/monitoreo-obsnev/monitoreo/wiki):
[QGIS](https://github.com/monitoreo-obsnev/monitoreo/wiki/QGIS),
[MCP](https://github.com/monitoreo-obsnev/monitoreo/wiki/MCP),
[Python](https://github.com/monitoreo-obsnev/monitoreo/wiki/Python) y
[R](https://github.com/monitoreo-obsnev/monitoreo/wiki/R).

| Herramienta | Para quién | Dónde |
|---|---|---|
| Paquete de Python `monitoreo` | scripts, cuadernos, línea de comandos | `src/monitoreo` |
| Plugin de QGIS **MonitorEO** | usuarios de QGIS 4.0.3 o posterior | `qgis/monitoreo_qgis` |
| Servidor MCP | Claude u otros modelos de lenguaje | `src/monitoreo/mcp_server.py` |
| Paquete de R `monitoreo` | R, con `rgee` | `r/monitoreo` |
| [Visor de resultados](#visor-de-resultados) | cualquiera, en el navegador (publican los administradores) | `src/monitoreo/viewer`, `monitoreo publish` |

Qué calculan, sobre una región (un área protegida de WDPA, una ecorregión, un rectángulo, un punto, una capa o un
GeoJSON):

- **Series temporales**: un valor por día, 16 días, mes o año y por cada polígono de la región, con el número de
  imágenes y de píxeles válidos de cada valor; en tabla, CSV y gráfica.
- **Mapas** de la variable agregada en el tiempo (p. ej. la mediana del NDVI de un periodo) como capa de teselas de
  Earth Engine: se ven en QGIS, Leaflet o rgee sin descargar nada.
- **Estadísticas** de esos mapas en cada polígono.
- **Tendencias estacionales**: para cada mes, cada 16 días o el año, la tendencia de sus valores a lo largo de los
  años (test de Mann-Kendall y pendiente de Sen), en tabla para la región o en mapa píxel a píxel.
- **Comparación de dos periodos** (el de referencia y otro): la media de cada parte del año en cada periodo y su
  diferencia, en tabla y gráfica, y el mapa de la diferencia.
- **Severidad de incendios**: el dNBR (NBR de Sentinel-2 o Landsat antes menos después del fuego) con las clases
  oficiales del USGS (Key y Benson, 2006), con la superficie de cada clase y el GeoTIFF del dNBR y su clase.
- **Exportaciones** a Google Drive de mapas (GeoTIFF) y series (CSV) grandes.
- **Descargas** de GeoTIFF a tu ordenador: un mapa, o una **receta** de varias variables y métricas en rejillas
  alineadas sobre un área de estudio y, con un píxel más grueso, sobre las ecorregiones que toca (las variables de
  entrada de un modelo; es lo que usa [eHabitat+](https://github.com/javimarlop/eHabpy)).

Variables: las 32 del catálogo de MonitorEO (NDVI, EVI, NDWI, LSWI, NDSI, NDCI, albedo, temperatura de superficie,
evapotranspiración, calor latente, LAI, clorofila, aerosoles) de Sentinel-2, Landsat 5-9 y MODIS, el NBR de
Sentinel-2 y Landsat (incendios, `catalog.EXTRA`) y cualquier otra colección o imagen de Earth Engine. Por defecto se aplican los **filtros por píxel** de MonitorEO (nubes, agua,
nieve, aerosoles); las nubes de Sentinel-2 se quitan con Cloud Score+.

Todo se calcula con **la cuenta de Earth Engine de cada usuario** y su proyecto de Google Cloud: no hay servidor
que alojar ni coste (el uso no comercial de Earth Engine es gratuito, con una cuota mensual por proyecto). Los
resultados de un análisis se pueden publicar para cualquiera, sin cuenta, en el [visor de resultados](#visor-de-resultados).

## Antes de empezar: cuenta de Earth Engine

1. Un proyecto de Google Cloud registrado en Earth Engine para uso no comercial
   (https://developers.google.com/earth-engine/guides/access).
2. Iniciar sesión una vez en el ordenador:

   ```bash
   earthengine authenticate
   ```

   (en QGIS, el botón **Autenticar…** del panel hace lo mismo). Las credenciales se guardan en
   `~/.config/earthengine/credentials` y las usan todas las herramientas.
3. El proyecto se indica en cada herramienta o en la variable de entorno `EE_PROJECT`.

## Instalación (Python, MCP y R)

Con [Miniforge](https://github.com/conda-forge/miniforge) (solo conda-forge; Miniconda usa por defecto el canal
`defaults` de Anaconda, cuyas condiciones exigen licencia a organizaciones grandes) y el fichero `environment.yml` de
este repositorio, que instala `monitoreo` desde GitHub:

```bash
conda env create -f environment.yml
conda activate monitoreo
```

o con pip en cualquier entorno de Python 3.9 o posterior:

```bash
pip install "monitoreo[mcp,plot] @ https://github.com/monitoreo-obsnev/monitoreo/archive/refs/heads/main.zip"
```

GDAL solo hace falta para leer ficheros vectoriales como región y descargar GeoTIFF directamente; el entorno de conda
lo trae.

## Python

```python
from monitoreo import services as mo

mo.init('mi-proyecto')                       # o la variable EE_PROJECT
mo.find_protected_areas('Sierra Nevada')     # SITE_ID = ID de WDPA (Parque Nacional: 389011)

ts = mo.time_series({'wdpa_id': 389011}, 'NDVI', 'Sentinel-2', '2020-01-01', '2021-12-31',
                    step='monthly', metric='mean', stat='mean', csv='ndvi.csv', chart='ndvi.png')
ts['rows'][:2]   # [{'region': 'Sierra Nevada', 'date': '2020-01-01', 'value': 0.34, 'n_pixels': ..., 'n_images': 31}, ...]

capa = mo.map_layer({'wdpa_id': 389011}, 'LST', 'Modis', '2021-06-01', '2021-08-31', metric='mean',
                    thumbnail='lst.png')
capa['url']      # https://earthengine.googleapis.com/v1/projects/.../tiles/{z}/{x}/{y}

mo.region_stats({'ecoregion_id': 793}, 'NDVI', 'Modis', '2021-01-01', '2021-12-31')
tarea = mo.export_image({'wdpa_id': 389011}, 'NDVI', 'Sentinel-2', '2021-01-01', '2021-12-31',
                        resolution=10, folder='MonitorEO')
mo.task_status(tarea['operation'])
```

Regiones: `{'wdpa_id': 389011}` (o una lista), `{'wdpa_name': 'Sierra Nevada'}`, `{'ecoregion_id': 793}`,
`{'ecoregion_at': [lon, lat]}`, `{'bbox': [oeste, sur, este, norte]}`, `{'point': [lon, lat], 'buffer': 1000}`,
`{'geojson': ...}` (geometría, Feature o FeatureCollection; `name_field` da el nombre de cada polígono) o
`{'file': 'zonas.gpkg', 'name_field': 'nombre'}`. Con varios polígonos hay una serie por polígono.

Opciones comunes: `season=['06-01', '09-30']` (solo esos días de cada año), `quality={'snow': False}` (filtros por
píxel: `clouds`, `water`, `snow`, `aerosols`, `True`, `False` o `'auto'`; `cloud_score: None` usa la máscara SCL de
MonitorEO en lugar de Cloud Score+), `metric` (`mean`, `median`, `min`, `max`, `pN`...) y, en los mapas,
`temporal='annual'` + `interannual='median'` (la métrica de cada año y después entre años).

Línea de comandos:

```bash
monitoreo list --sensor Landsat
monitoreo info NDVI --sensor Modis
monitoreo parks "Doñana"
monitoreo series NDVI --sensor Sentinel-2 --region '{"wdpa_id": 389011}' --start 2020-01-01 --end 2021-12-31 --csv ndvi.csv --png ndvi.png
monitoreo download receta.yaml --area zona.gpkg --out variables --dry-run
monitoreo trend NDVI --sensor Modis --region '{"wdpa_id": 389011}' --start 2010-01-01 --end 2023-12-31 --step monthly --png tendencias.png
monitoreo compare NDVI --sensor Modis --region '{"wdpa_id": 389011}' --start 2010-01-01 --end 2014-12-31 --other-start 2019-01-01 --other-end 2023-12-31
```

### Tendencias estacionales y comparación de periodos

En `monitoreo.trends`, cada año da un valor de cada **parte del año** (`step`): `'monthly'`, los 12 meses
(`m01`…`m12`); `'16-day'`, 23 partes de 16 días desde el 1 de enero (días 1-16, 17-32… 353-366: `p01`…`p23`), o
`'annual'`, el año (`all`); ese valor es la métrica (`metric`, la media por defecto) de las imágenes de esa parte en
ese año. La tendencia de cada parte a lo largo de los años: número
de años con datos (`n`), τ de Kendall, Z de Mann-Kendall (aproximación normal, sin corrección por empates) y su
p-valor bilateral, pendiente de Sen (cambio por año) y su valor en el primer año (`intercept`). Mejor con 8 años o más.

```python
t = mo.trend_table({'wdpa_id': 389011}, 'NDVI', 'Modis', '2010-01-01', '2023-12-31', step='monthly',
                   csv='tendencias.csv', chart='tendencias.png')      # tendencia de la media de la región
t['rows'][0]   # {'key': 'm01', 'label': 'enero', 'n': 14, 'tau': -0.32, 'p_value': 0.11, 'slope': -0.0039, ...}
mo.download_trend({'wdpa_id': 389011}, 'NDVI', 'Modis', '2010-01-01', '2023-12-31', step='monthly', part=7,
                  path='tendencia_julio.tif')      # píxel a píxel: bandas slope, tau, z, p_value, intercept, n
mo.trend_map(..., step='annual', output='slope', alpha=0.05)    # teselas, solo los píxeles con p < 0,05

c = mo.compare_series({'wdpa_id': 389011}, 'NDVI', 'Modis', '2010-01-01', '2014-12-31',   # periodo de referencia
                      '2019-01-01', '2023-12-31', step='monthly', chart='comparacion.png')  # otro periodo
c['profile'][0]   # {'label': 'enero', 'reference': 0.53, 'other': 0.50, 'difference': -0.027, ...}
mo.download_comparison({'wdpa_id': 389011}, 'NDVI', 'Modis', '2018-01-01', '2021-12-31', '2023-01-01',
                       '2023-12-31', metric='median', path='diferencia.tif')   # bandas difference, reference, other
```

Severidad de un incendio (`monitoreo.fire`): dNBR = NBR antes − NBR después, cada uno la mediana de las imágenes de
un periodo antes y otro después del fuego, clasificado con la escala del USGS (rebrote alto y bajo, no quemado,
severidad baja, moderada-baja, moderada-alta y alta; quemado desde dNBR 0,1), como la práctica recomendada de
UN-SPIDER para Earth Engine:

```python
s = mo.burn_severity({'wdpa_id': 389013}, 'Sentinel-2', '2023-05-15', '2023-08-14',   # antes del incendio
                     '2023-09-15', '2023-11-30', path='severidad.tif', csv='severidad.csv')   # después
s['burned_ha']    # {'El Teide': 956.4}: hectáreas con dNBR >= 0,1
s['classes'][3]   # {'class': 1, 'label': 'Severidad baja', 'dnbr_min': 0.1, 'dnbr_max': 0.27, 'ha': 559.0, ...}
```

### Descarga de variables en GeoTIFF

Un mapa, directamente (Earth Engine lo calcula en teselas; para regiones pequeñas, de unos millones de píxeles):

```python
mo.download_image({'wdpa_id': 389011}, 'NDVI', 'Sentinel-2', '2021-01-01', '2021-12-31', metric='p95',
                  resolution=20, path='ndvi_p95.tif')
```

Varias variables, en rejillas alineadas (mismo CRS, bordes múltiplos del píxel, NoData -9999), con una **receta**
(`monitoreo.recipe`):

```yaml
crs: auto                          # WGS 84 / UTM del centro del área de estudio, o p. ej. EPSG:25830
study: {resolution: 10, buffer: 500, drive: false}      # área de estudio: rectángulo + buffer (m), descarga directa
ecoregion: {resolution: 100, drive: true}               # opcional: ecorregiones RESOLVE 2017 que toca, vía Drive
drive_folder: MonitorEO
period: ['2018-01-01', '2021-12-31']
quality: {clouds: true, water: true, snow: true, aerosols: true, cloud_score: 0.6}
variables:
  - {index: NDVI, sensor: Sentinel-2, metric: [p95, p5]}   # un fichero por métrica
  - {index: LSWI, sensor: Sentinel-2, metric: median}
  - {index: LST, sensor: Modis, temporal: annual, metric: max, interannual: median}
  - {name: slope, image: COPERNICUS/DEM/GLO30_2024_1, band: DEM, terrain: slope}
  - {name: precip, image: WORLDCLIM/V1/BIO, band: bio12}
```

```python
mo.download_variables('receta.yaml', 'zona.gpkg', 'variables', dry_run=True)   # rejillas, tamaños, nº de imágenes
mo.download_variables('receta.yaml', 'zona.gpkg', 'variables', log=print)      # o el área: {'wdpa_id': 389011}
```

Las variables del área de estudio quedan en `variables/` (`1_NDVI_S2_p95.tif`, `2_NDVI_S2_p5.tif`, ... en el orden
de la receta) y las de las ecorregiones en `variables/ecoregion/`, con sus polígonos en `ecoregions.gpkg` (fuera de
ellas, sin datos). `monitoreo.json` guarda con qué se hizo cada fichero: al repetirlo solo se descarga lo que haya
cambiado. Las rejillas con `drive: true` se exportan a Google Drive (sin límites de tamaño ni de tiempo, mejor para
las grandes) y se importan desde Google Drive para escritorio al terminar; si se interrumpe, al repetirlo no se
lanzan otra vez: se esperan y se importan.

## Plugin de QGIS

Instalación: descarga `monitoreo_qgis-<versión>.zip` de la última release
(https://github.com/monitoreo-obsnev/monitoreo/releases/latest) e instálalo en QGIS con **Complementos > Administrar
e instalar complementos > Instalar a partir de ZIP**. El zip lleva dentro `monitoreo` y la librería de Earth Engine con sus dependencias
(Python puro, válido en Windows, macOS y Linux), así que no hay que instalar nada más. Requiere QGIS 4.0.3 o
posterior (Qt6, Python 3.12); en QGIS 3 funcionan las versiones del plugin hasta la 0.3.3.

El botón **MonitorEO** de la barra de herramientas (o el menú Web) abre un panel con:

- **Google Earth Engine**: el proyecto, **Conectar** y **Autenticar…**.
- **Región**: una capa de polígonos (las entidades seleccionadas o todas, con un campo para su nombre), la
  extensión del mapa, un área protegida (buscando por nombre en WDPA) o la ecorregión del centro del mapa.
- **Variable**: variable y sensor del catálogo, periodo, temporada y filtros por píxel. **Comparar con otro
  periodo**: con la casilla marcada, la serie temporal compara el periodo de referencia con el otro (la media de cada
  mes, 16 días o año en cada periodo y su diferencia) y el mapa es la diferencia (otro − referencia, con los dos
  periodos como bandas).
- **Serie temporal**: paso, métrica de cada paso y estadístico de la región. Abre una ventana con la gráfica, la tabla
  y los botones para guardar el CSV y la gráfica. Las series, tendencias y comparaciones calculadas en la sesión quedan
  en la lista **Series**: **Ver** vuelve a abrir su ventana.
- **Tendencias (Mann-Kendall y Sen)**: partes del año (año, meses o 16 días) y métrica de cada año. **Tabla de
  tendencias de la región**: la tendencia de cada parte, con la gráfica de los valores anuales y sus rectas de Sen.
  **Mapa de tendencia** de una parte del año: GeoTIFF con la pendiente de Sen, τ, Z, p-valor, valor inicial y años de
  cada píxel (consultables con Identificar), opcionalmente solo los píxeles con tendencia significativa.
- **Mapa**: añade la variable agregada en el tiempo como GeoTIFF temporal, con la rampa de colores de MonitorEO
  (percentiles 5 y 95) y el mapa centrado en la región; sus valores se consultan con la herramienta **Identificar**.
  Va a la resolución de los datos o, si la región pasa de 4 millones de píxeles, con píxeles 2, 3... veces mayores
  (para la resolución completa, la exportación a Google Drive). Si no se puede descargar, añade la capa de teselas de
  Earth Engine (solo colores).
- **Exportar a Google Drive**: el mapa en GeoTIFF y la serie en CSV. El panel sigue las tareas y, si Google Drive
  para escritorio está instalado, carga el GeoTIFF en el proyecto al terminar.

Los cálculos van en tareas de QGIS (barra de tareas), sin bloquear QGIS.

**Publicar una versión del plugin**: sube `version=` en `qgis/monitoreo_qgis/metadata.txt`, haz commit y push, y
publica una release en GitHub (*Releases > Draft a new release*, etiqueta nueva con esa versión, p. ej. `v0.2.0`,
*Publish release*). Unos minutos después, el flujo `.github/workflows/qgis-plugin.yml` le adjunta el zip del plugin,
generado en GitHub (se sigue en la pestaña *Actions*). También vale subir la etiqueta desde GitHub Desktop
(*History*, botón derecho sobre el commit, *Create Tag…* `v0.2.0`, *Push origin*): el flujo crea la release. Falla
si la etiqueta no coincide con `version=` (`0.2` y `v0.2.0` valen para `0.2.0`). Para adjuntar el zip a una release
que ya existe: *Actions > Plugin de QGIS > Run workflow*, con su etiqueta.

Para generar el zip en local: `python qgis/build_plugin.py` (descarga las dependencias; necesita internet; queda
en `dist/`). Prueba sin ventana con el Python de QGIS:
`EE_PROJECT=... /Applications/QGIS-final-4_0_3.app/Contents/MacOS/python qgis/test_plugin.py`.

## Servidor MCP (Claude y otros modelos de lenguaje)

Herramientas: `list_variables`, `describe_variable`, `find_protected_areas`, `time_series` (tabla, CSV y gráfica),
`map_layer` (URL de teselas y vista previa), `region_stats`, `export_image_to_drive`,
`export_time_series_to_drive`, `task_status`, `download_image` y `download_variables` (GeoTIFF en el ordenador; la
segunda con una receta, como JSON), las tendencias estacionales `trend_table`, `trend_map` y `download_trend`, la
comparación de periodos `compare_series`, `compare_map` y `download_comparison`, la severidad de incendios
`burn_severity`, `connect` y, para los administradores del [visor de resultados](#visor-de-resultados),
`publish_report`. Los CSV, PNG y GeoTIFF se guardan en `MONITOREO_OUTPUT` (por
defecto `~/MonitorEO`).

**Siempre la última versión de GitHub**: al arrancar, `monitoreo mcp` compara el paquete instalado con el último
commit de GitHub y, si no es el mismo, instala esa versión con pip en su entorno y arranca con ella. Sin conexión
avisa y arranca con la instalada; `monitoreo mcp --no-update` se salta la comprobación. Solo se actualiza el paquete
instalado en el entorno: un clon o una copia de desarrollo (`pip install -e`) no se tocan (el servidor avisa de que
usa una copia local).

Claude Desktop (`claude_desktop_config.json`), con el entorno de conda (que trae GDAL, necesario para las descargas
en GeoTIFF y las regiones desde ficheros):

```json
{
  "mcpServers": {
    "monitoreo": {
      "command": "/ruta/a/miniforge3/envs/monitoreo/bin/monitoreo",
      "args": ["mcp"],
      "env": {"EE_PROJECT": "mi-proyecto", "MONITOREO_OUTPUT": "/Users/yo/MonitorEO", "PYTHONNOUSERSITE": "1"}
    }
  }
}
```

(`PYTHONNOUSERSITE` evita que paquetes instalados con `pip install --user` en `~/.local` sustituyan a los del entorno.)

Claude Code:

```bash
claude mcp add monitoreo -e EE_PROJECT=mi-proyecto -e PYTHONNOUSERSITE=1 -- /ruta/a/miniforge3/envs/monitoreo/bin/monitoreo mcp
```

Ejemplo de petición: *"Compara el NDVI mensual de Sentinel-2 de 2019 a 2023 en el Parque Nacional de Sierra Nevada
y en el de Doñana y dame el CSV"*. Las series largas sobre áreas grandes tardan minutos: mejor con paso mensual o
anual, o exportadas a Drive.

## R

```r
install.packages(c("remotes", "reticulate"))   # y rgee, opcional
remotes::install_github("monitoreo-obsnev/monitoreo", subdir = "r/monitoreo")
# una versión concreta (la que se cita con su DOI): ref = "v0.3.2"; desde un clon del repositorio:
# install.packages("r/monitoreo", repos = NULL, type = "source")
library(monitoreo)

# El Python de reticulate debe tener el paquete monitoreo: el del entorno de conda,
Sys.setenv(RETICULATE_PYTHON = "/ruta/a/miniforge3/envs/monitoreo/bin/python")
# o el de rgee, instalándolo en él con mo_install().
mo_init("mi-proyecto")

mo_protected_areas("Sierra Nevada")
ts <- mo_time_series(mo_wdpa(389011), "NDVI", "Sentinel-2", "2020-01-01", "2021-12-31", step = "monthly")
mo_plot(ts)                                   # ggplot2
write.csv(ts, "ndvi.csv", row.names = FALSE)

zonas <- sf::st_read("zonas.gpkg")
mo_time_series(mo_sf(zonas, "nombre"), "LST", "Landsat", "2015-01-01", "2023-12-31", step = "annual", metric = "max")

capa <- mo_map_layer(mo_wdpa(389011), "NDVI", "Sentinel-2", "2021-01-01", "2021-12-31")
mo_leaflet(capa)                              # leaflet

x <- mo_image(mo_wdpa(389011), "LST", "Modis", "2021-06-01", "2021-08-31", metric = "mean")
rgee::Map$addLayer(x$image, x$vis, x$name)   # rgee

mo_download_variables("receta.yaml", "zona.gpkg", "variables")   # GeoTIFF de una receta (o yaml::read_yaml())
terra::rast(list.files("variables", "\\.tif$", full.names = TRUE))

tr <- mo_trend_table(mo_wdpa(389011), "NDVI", "Modis", "2010-01-01", "2023-12-31", step = "monthly")
cmp <- mo_compare_series(mo_wdpa(389011), "NDVI", "Modis", "2010-01-01", "2014-12-31", "2019-01-01", "2023-12-31")
terra::rast(mo_download_trend(mo_wdpa(389011), "NDVI", "Modis", "2010-01-01", "2023-12-31", "tendencia.tif")$file)
```

Funciones: `mo_init`, `mo_install`, `mo_variables`, `mo_describe`, `mo_protected_areas`, regiones (`mo_wdpa`,
`mo_ecoregion`, `mo_bbox`, `mo_point`, `mo_geojson`, `mo_sf`), `mo_time_series`, `mo_plot`, `mo_map_layer`,
`mo_leaflet`, `mo_image`, `mo_region_stats`, `mo_download_image`, `mo_download_variables`, tendencias
(`mo_trend_table`, `mo_trend_map`, `mo_download_trend`), comparación de periodos (`mo_compare_series`,
`mo_compare_map`, `mo_download_comparison`), severidad de incendios (`mo_burn_severity`), `mo_export_image`, `mo_export_time_series` y `mo_task_status`.

## Visor de resultados

Los resultados de un análisis se publican en un **visor web estático** que cualquiera consulta en el navegador, sin
cuenta de Earth Engine y sin gastar su cuota: un catálogo de informes con filtros (parque, variable, tipo de análisis
y año de los datos) y una página por informe con el **mapa interactivo** de cada GeoTIFF (el valor de todas sus capas
al pulsar un píxel), los **gráficos interactivos** de cada CSV, los textos, las descargas y la llamada que produjo cada
resultado. Los mapas son Cloud Optimized GeoTIFF que el navegador lee por partes (OpenLayers y geotiff.js), y los
gráficos, Vega-Lite: no hay servidor de mapas (ni GeoServer ni GeoNode) ni teselas que caduquen. Solo publican los
administradores: el sitio no tiene cuentas ni formularios, y publica quien puede escribir en él. El sitio público es
<https://monitoreo-obsnev.github.io/resultados/>, del repositorio
[monitoreo-obsnev/resultados](https://github.com/monitoreo-obsnev/resultados).

```bash
monitoreo publish informe.yaml --site ~/visor   # GeoTIFF a COG, CSV, report.json y catalog.json, y el visor
monitoreo serve ~/visor                         # el visor en este ordenador: http://127.0.0.1:8000/
monitoreo publish --check --site ~/visor        # comprueba el catálogo y cada informe
monitoreo publish --remove ID --site ~/visor    # retira un informe
monitoreo publish --site ~/visor                # actualiza el visor (tras actualizar monitoreo) y el catálogo
```

Un informe es un YAML con sus textos (en español) y los resultados del análisis: las respuestas de las herramientas
MCP guardadas con su llamada, las llamadas y resultados de `monitoreo.services` o los ficheros que escribió el
servidor MCP (que guarda cada llamada en `MONITOREO_OUTPUT/calls.jsonl`). Un YAML puede tener varios informes en
`reports:`. Ver `monitoreo.publish` y el manual en la [wiki](https://github.com/monitoreo-obsnev/monitoreo/wiki/Visor-de-resultados).

```yaml
id: 2026-10-sierra-nevada-verdor
title: ¿En qué época del año ha cambiado el verdor desde 2001, y dónde?
summary: Solo septiembre tiene una tendencia significativa del EVI (+0,008 por década, p = 0,015).
answer: El EVI medio del parque sube en 9 de los 12 meses...
method: Tendencias con el test de Mann-Kendall y la pendiente de Sen...
region: {name: Sierra Nevada, full_name: Parque Nacional de Sierra Nevada, area_km2: 859}
authors: [Observatorio de Cambio Global de Sierra Nevada (OBSNEV), Universidad de Granada]
files: mcp_out                                 # dónde buscar por su nombre los ficheros de los resultados
results:
  - answer: data/sn_trendmap.json              # respuesta de download_trend con su llamada
    title: Tendencia del EVI medio anual en cada píxel, 2001-2024
    palette: [8c510a, f2efe6, 01665e]
  - answer: data/sn_trend.json                 # respuesta de trend_table
  - answer: data/sn_series.json                # respuesta de time_series
downloads: [{path: informe.pdf, title: Informe completo (PDF)}]
license: CC-BY-4.0                             # la de sus datos y mapas (por defecto)
```

Los datos y mapas se publican con licencia [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.es): se
pueden reutilizar para cualquier fin, también comercial, citando la fuente (cada informe dice cómo citarlo). Un
informe puede dar otra en `license:` (`CC-BY-SA-4.0`, `CC0-1.0` o `{name, url, text}`); el visor la muestra en el
informe y en su cita, y la del sitio en el pie de cada página.

En Python, `services.publish_report('informe.yaml', site='~/visor')` (o un diccionario); en el servidor MCP,
`publish_report` con los ficheros que escribieron las otras herramientas y los textos.

El sitio (`--site`, la variable `MONITOREO_SITE` o `~/MonitorEO/visor`) es una carpeta estática: `index.html` (el
catálogo), `report.html`, `assets/`, `catalog.json` y `reports/<id>/` con `report.json`, `maps/*.tif` (COG),
`data/*.csv`, `files/` (gráficos PNG y otras descargas) y `thumbnail.png`. Se publica con cualquier servidor web que
atienda peticiones por rangos de bytes. El sitio público es una copia de trabajo del repositorio
`monitoreo-obsnev/resultados` (aparte, para no cargar este con los mapas), servido por GitHub Pages desde su rama
`main`: publicar es publicar en ella y subir el cambio, y su historia guarda quién publicó qué.

```bash
git clone git@github.com:monitoreo-obsnev/resultados.git ~/resultados    # una vez
monitoreo publish informe.yaml --site ~/resultados
cd ~/resultados && git add -A && git commit -m "Informe ..." && git push   # en línea en un minuto
```

## Catálogo

`src/monitoreo/catalog.json` es el catálogo de variables, que se mantiene en este repositorio: colección, fórmula,
escala y desplazamiento de las bandas, unidad, bandas de calidad y rampa de colores de cada una. `catalog.EXTRA`
añade el NBR de Sentinel-2 y Landsat.

Detalles del cálculo, en el código:

- `FIXES` en `catalog.py`: la escala del LAI de MCD15A3H es 0.1, no 0.01.
- La escala y el desplazamiento de las bandas se aplican antes de la fórmula (EVI, el albedo y la clorofila de
  Sentinel-2 necesitan reflectancias, no las bandas sin escalar).
- Los nombres de banda de las fórmulas se comparan sin mayúsculas (`LST_day_1km` de las entradas 15 y 16).
- Los valores de bandera de MODIS (p. ej. 250 = nube en `NDSI_Snow_Cover`) se descartan siempre.
- Landsat 7 solo se usa hasta el 31-5-2003, como dice el catálogo.
- WDPA cambió su esquema en Earth Engine: el ID es ahora `SITE_ID` (antes `WDPAID`).
